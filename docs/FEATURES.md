# 기능 설명

현재 Spring Boot 프로젝트의 구현을 기준으로 작성한 사용자·운영자 안내입니다.
프로그램 실행 방법은 [README](../README.md), 개발 구조는 [구조 설명](ARCHITECTURE.md)을 참고하세요.

## 1. 시스템 목적과 기본 흐름

관리할 법령·행정규칙을 등록하고 개정을 확인한 뒤, 관련 사규의 검토와 수정 기록을 관리합니다.
KOSHA 가이드와 안전보건 뉴스도 같은 웹 화면에서 조회합니다.

```text
외부 API 설정 → 법령 등록 → 동기화 → 법령 개정 확인
                              ↓
             사규의 근거 법령·키워드와 연결
                              ↓
             법령 영향 검토 → 사규 수정 → 사규 이력 보존
```

처음 사용할 때는 다음 순서로 설정합니다.

1. 설정에서 국가법령정보센터 OC 키를 저장합니다.
2. 법령 마스터에서 관리할 법령을 검색·등록합니다. 설정의 기본 법령 세트 추가도 사용할 수 있습니다.
3. 사규를 등록하면서 근거 법령과 필요한 키워드를 지정합니다.
4. 상단의 **지금 동기화**로 법령 정보를 가져옵니다.
5. 법령 개정 이력과 법령 영향에서 검토 상태를 관리합니다.
6. 실제 사규를 변경했다면 사규 화면에서 버전·변경 사유 등을 저장합니다.

## 2. 메뉴 안내

| 메뉴 | 주소 | 역할 |
| --- | --- | --- |
| 대시보드 | `/dashboard` 또는 `/` | 개정·검토 현황, 사규 영향, 신규 고시 후보 요약 |
| 안전보건 뉴스 | `/news` | 수집된 뉴스 검색과 보관 |
| 법령 마스터 | `/laws` | 추적할 법령·행정규칙 관리 |
| 법령 개정 이력 | `/revisions` | 감지된 법령 개정의 검토 상태 관리 |
| KOSHA 가이드 | `/kosha-guides` | 기술지침 등록, 원문과 PDF 관리 |
| 키워드 검색 | `/search` | 저장된 법령명·본문 검색 |
| 사규 | `/documents` | 사내 절차서·지침서·작업표준 관리 |
| 사규 개정 이력 | `/document-revisions` | 사규 저장 당시의 내용 조회 |
| 법령 영향 | `/document-impacts` | 사규와 관련된 법령 개정 검토 |
| 설정 | `/settings` | 외부 연동, 후보 탐색, 캐시, 뉴스 설정 |

### 대시보드

- 관리 중인 법령 수, 등록 사규 수, 미검토·검토중·반영완료 개정 수를 표시합니다.
- 관리 중인 법령의 미검토·검토중 개정을 최신순 최대 200건 조회합니다.
- 관련 법령 개정으로 검토가 필요한 사규를 보여줍니다.
- 신규 고시 후보를 법령 마스터에 등록하거나 무시할 수 있습니다.
- 뉴스 게시판에서 분류별 기사와 원문 링크를 확인합니다.
- 검색창에 입력한 문구로 키워드 검색 화면에 이동합니다.

상단 새 개정 알림의 확인 여부는 브라우저 저장소에 기록합니다. 알림을 눌러 확인해도
법령의 검토 상태가 자동으로 반영완료가 되지는 않습니다.

### 법령 마스터

법령과 행정규칙을 이름으로 검색해 추적 대상으로 등록합니다. 목록에서는 공포·시행 정보,
연결된 사규 수, 미검토 개정 수를 확인하고 법령별 개정 이력으로 이동할 수 있습니다.

등록 시 최초 동기화와 본문 캐시를 시도합니다. 외부 조회 실패 시 등록은 완료되고
후속 동기화가 필요하다는 안내를 반환할 수 있습니다. 이미 추적 중인 법령의 중복 등록은 제한합니다.
추적 취소는 법령을 비활성화하는 방식이며 기존 개정 이력을 함께 삭제하지 않습니다.
같은 법령을 다시 등록하면 기존 법령 항목을 활성화합니다.

### 법령 개정 이력

동기화 시 **공포번호·공포일자·시행일자** 변화를 비교해 개정을 기록합니다.
첫 확인 시 공포일자 또는 시행일자가 있으면 최초 확인 기록을 남깁니다.
기록에는 현재와 이전 공포·시행 정보, 감지 시각, 검토 상태 등을 저장합니다.
조문 내용 전체를 줄 단위로 비교해 변경 문장을 제시하는 기능은 아닙니다.

| 검토 상태 | 사용 의미 |
| --- | --- |
| 미검토 | 아직 내용을 확인하지 않음 |
| 검토중 | 사내 적용 여부와 조치를 검토 중 |
| 반영완료 | 필요한 조치를 반영했다고 기록 |
| 해당없음 | 적용 대상이 아니라고 기록 |

상태별·법령별 조회, 화면 내 이름 검색, 선택 항목 일괄 상태 변경과 삭제를 지원합니다.
검토 상태는 법령 개정 한 건에 저장합니다. 같은 개정이 여러 사규와 연결되어 있으면
한 화면에서 상태를 바꾼 결과가 다른 사규에도 공유됩니다. 사규별 독립 검토 상태는 제공하지 않습니다.

### 사규

절차서·지침서·작업표준·기타 문서를 등록·수정·삭제합니다. 문서번호, 제목, 개정번호,
개정일자, 담당자, 문서 링크, 키워드, 비고와 근거 법령을 저장합니다.
제목·문서번호·담당자·키워드·근거 법령으로 화면 내 검색과 선택 삭제를 할 수 있습니다.

문서 정보, 근거 법령 연결, 변경 이력은 한 트랜잭션으로 저장합니다.
변경 사유와 변경 담당자를 함께 입력할 수 있습니다. 사규의 파일은 링크로 관리하며,
KOSHA 가이드처럼 파일 자체를 업로드하는 기능은 제공하지 않습니다.

### 사규 개정 이력

사규의 등록·수정·근거 법령 연결 변경·삭제 시점 내용을 보존합니다.
제목, 문서번호, 버전, 개정일, 담당자, 태그, 비고, 문서 링크, 연결 법령 ID 목록,
변경 사유·변경자·저장 시각을 확인할 수 있습니다.

- 사규별 이력과 제목 검색을 제공하며 화면에서는 최신 200건을 표시합니다.
- 이력이 없는 기존 사규를 처음 수정하면 수정 전 상태도 기록합니다.
- 사규를 삭제해도 기존 이력과 삭제 시점 기록은 남습니다.
- 과거 시점의 파일 복사본을 보관하거나 사규를 이전 버전으로 자동 복원하지는 않습니다.
- 변경자 필드는 사용자 입력값입니다. 로그인 계정을 자동 기록하는 감사 로그와는 다릅니다.

### 법령 영향

현재 사규를 기준으로 아래 중 하나에 해당하는 관리 중인 법령의 개정을 모읍니다.

- 사규에 근거 법령으로 직접 연결한 법령
- 사규 키워드가 법령명 또는 저장된 본문과 일치하는 법령

상태 필터, 법령명·사규명 검색, 선택 항목의 일괄 검토 상태 변경을 지원합니다.
본문 키워드 매칭은 캐시된 본문을 사용하므로 캐시가 없는 법령은 본문 기준으로 매칭되지 않습니다.
법령 영향에서 상태를 변경해도 사규의 개정번호나 내용이 자동 변경되지는 않습니다.

### KOSHA 가이드

- 지침번호, 분야, 제목, 제개정일자, 원문 링크, 본문과 비고를 수동 등록·수정합니다.
- 목록을 탭 또는 쉼표로 구분해 붙여 넣는 일괄 등록을 지원합니다.
- 인증키를 설정하면 API 동기화 버튼으로 가이드 목록을 수집합니다.
- 등록한 가이드에 PDF를 첨부하고 열기·다운로드·첨부 삭제를 할 수 있습니다.
- PDF는 최대 20MB이며, 본문 캐시 채우기로 PDF 텍스트를 추출해 검색에 사용합니다.
- 제목·본문 검색과 결과 미리보기를 제공합니다.

PDF에 텍스트가 없는 스캔 이미지라면 본문이 추출되지 않을 수 있습니다. OCR 기능은 없습니다.
KOSHA 가이드 API 동기화는 수동 기능이며, 현재 정기 스케줄러에는 포함하지 않습니다.

### 키워드 검색과 법령 본문 캐시

법령·행정규칙의 저장된 이름과 본문을 검색하며, 일치 위치와 앞뒤 문맥을 보여줍니다.
가능한 경우 조문 링크를 함께 제공합니다. 검색은 최대 200건을 반환합니다.

캐시를 채우는 방법은 세 가지입니다.

1. 등록 법령 동기화: 추적 중인 법령 본문 갱신.
2. 설정의 본문 캐시 새로고침: 추적 법령과 탐색 키워드·부처 조건을 적용한 추가 법령 수집.
3. 전체 법령 캐시: 전체 목록을 순회하며 본문을 받는 백그라운드 작업. 공포·시행 정보가 같고 본문이 있으면 상세 수집을 건너뜁니다.

전체 캐시는 처리 건수, 건너뛴 건수, 시작·종료 시각과 오류를 표시합니다.
진행 상태는 서버 메모리에 있으므로 재시작하면 이어서 실행되지 않습니다. 이미 저장한 본문은 DB에 남습니다.

### 안전보건 뉴스

RSS/Atom 피드에서 뉴스를 수집하고 카테고리·제목·기간·보관 여부로 검색합니다.
기본 피드는 고용노동부·안전보건공단·중대재해 키워드의 Google 뉴스 검색 RSS이며 설정에서 변경할 수 있습니다.

제목 유사성과 시각 등을 이용해 같은 사건으로 판단한 중복 기사를 정리합니다.
이 판별은 휴리스틱이며 완벽한 사건 분류를 보장하지 않습니다.
수집 작업 중 보관 기간이 지난 미보관 기사를 정리하며 기본 기간은 180일입니다.
발행 시각이 없으면 수집 시각을 사용합니다. 보관 처리한 기사는 기간별 자동 삭제에서 제외합니다.
뉴스 검색은 기본 200건, API 요청 상한은 300건이며 전체 일치 건수도 반환합니다.

### 설정과 공통 기능

설정에서는 기본 법령 세트 추가, 신규 고시 후보의 부처·키워드·기준일,
무시한 후보 복원, 외부 API 인증키, 본문 캐시와 뉴스 피드를 관리합니다.
후보 탐색 시 API 응답에 부처나 공포일자가 비어 있는 항목은 해당 조건만으로 제외하지 않습니다.

상단에서는 수동 동기화, 연동 상태 안내, 새 개정 알림과 도움말을 제공합니다.
외부 연동 상태 안내는 설정값과 저장 상태를 바탕으로 하며 외부 서비스 정상 동작을 보증하는 점검은 아닙니다.

## 3. 자동 실행과 수동 실행의 차이

| 작업 | 자동 실행 | 수동 실행 | 조건 |
| --- | --- | --- | --- |
| 법령 개정 확인·추적 본문 갱신·신규 고시 탐색 | 기본 24시간 간격 | 상단 지금 동기화 | 자동 실행은 OC 키가 설정되어 있어야 함 |
| 뉴스 수집·중복 및 기간 정리 | 기본 3시간 간격 | 설정의 뉴스 새로고침 | 로컬 프로필에서는 외부 뉴스 수집 생략 |
| 전체 법령 본문 캐시 | 매일 오전 1시, 한국 시간 | 설정의 지금 바로 시작 | 자동 실행 설정을 켜야 함 |
| KOSHA 목록·PDF 본문 | 없음 | 해당 메뉴 버튼 | API 키 또는 접근 가능한 PDF 필요 |

법령·뉴스 작업은 서버 시작 직후 실행하지 않습니다. 각각 설정된 지연 시간이 지난 후
처음 실행하고, **작업 완료 시점부터** 같은 간격을 기다립니다. 간격은 서버 환경변수
`AUTO_SYNC_DELAY_MS`, `NEWS_FETCH_DELAY_MS`로 지정하며 변경 후 재시작합니다.

모든 자동 작업은 서버가 실행 중일 때만 동작합니다. 꺼져 있던 시간의 예약 작업을
자동으로 보충하지 않으며, OS 작업 스케줄러용 별도 배치나 Python 동기화 스크립트는 포함하지 않습니다.
상단의 지금 동기화는 뉴스·KOSHA까지 한 번에 동기화하는 버튼이 아닙니다.

## 4. 다른 PC에서 사용할 때

저장소를 클론하면 소스, Gradle Wrapper, SQL, 화면과 이 문서가 내려옵니다.
다음 항목은 별도로 준비합니다.

| 항목 | 준비 방법 |
| --- | --- |
| GitHub 접근 | 비공개 저장소에 접근할 수 있는 계정으로 인증 |
| Java | JDK 17 설치, IntelliJ Project SDK와 Gradle JVM 설정 |
| 로컬 데이터 | 필요하다면 기존 서버를 종료한 뒤 `data/`를 백업·복사 |
| 운영 DB | 같은 Oracle에 접속하거나 별도 DB로 데이터 이관 |
| KOSHA 첨부 PDF | `data/kosha/` 또는 지정한 파일 저장 경로 복사 |
| 인증·접속 정보 | DB·로그인 환경변수 준비, API 키 설정 |

Git에는 DB 데이터, 첨부파일, 빌드된 JAR와 실제 인증 정보를 넣지 않습니다.
API 키를 화면에서 저장했다면 DB 설정에 들어 있으므로 DB를 새로 만들 때는 다시 설정해야 합니다.

`local` 프로필에서는 OC 키가 비어 있을 때 예시 법령을 사용합니다. OC 키를 입력하면
법령은 실제 API를 조회할 수 있지만 저장소는 여전히 H2이고 외부 뉴스 수집은 생략합니다.

## 5. 구현 범위

현재는 단일 서버 운영, 공통 로그인 계정과 브라우저 화면 사용을 기준으로 합니다.
사용자별 권한, 이메일·메신저 알림, 사규 승인 결재, 조문 차이 비교, 자동 사규 수정,
과거 파일 버전 복원은 구현되어 있지 않습니다.

이 문서는 코드에서 확인한 동작을 설명합니다. 이번 문서 작성에서 빌드·테스트·실행 검증은 하지 않았습니다.
